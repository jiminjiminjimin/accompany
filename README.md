# 안심 동행 — 최종 개발·보안·배포 보고서

최종 정리일: **2026-10-24** · Android 14(API 34) 이상 · 패키지 `com.example.pathreport` · 배포 버전 **1.0.2-test / versionCode 3**.

주간보호센터의 어르신 명단과 승하차장소를 관리하고, GPS로 등·하원 도착 시간을 추정해 기록하는 Android 앱입니다. 주요 기능은 구현했으며, 이번 버전에는 완료된 운행의 개별/전체 기록 삭제와 **“이 운행 전체 삭제”** 문구까지 포함했습니다. 서명된 Release 빌드이지만 운영 보안 인증을 받은 제품이라는 뜻은 아닙니다. 실제 회사 휴대폰과 차량에서의 인수 검증은 남아 있습니다.

이 README는 개발과 보안 검토를 시간순으로 정리한 최종 인수 자료입니다. 기존 README 및 일반인용 보고서 원문은 아래 접기 영역에 보존하고 모든 상세 문서를 연결했습니다. 과거 문서의 “현재”, “미완료”, “주소 저장”, “Debug 빌드”는 **해당 문서 작성 당시**를 뜻합니다. 최신 상태는 다음 요약을 먼저 확인하세요.

## 3. On-device 저장과 외부 통신 — 일반인용 최신 요약

이 앱은 **이름·좌표·운행 기록을 휴대폰 내부에 암호화해 저장**합니다. 서버 데이터베이스로 명단을 업로드하는 구조가 아니며, SQLite가 아닌 앱 전용 파일 `noBackupFilesDir/care-v1.enc`를 사용합니다. 저장할 때 메모리의 JSON 전체를 AES-256-GCM으로 암호화하고, 읽을 때 복호화합니다. Android Keystore가 키를 관리합니다. 암호화는 익명화가 아니므로 앱 화면·메모리에서는 원래 정보가 사용됩니다.

| 데이터 | 보관·전송 방식 | 주의점 |
| --- | --- | --- |
| 어르신 이름 | ID와 함께 암호화 파일, 운행 당시 스냅샷 | 삭제 범위를 명단과 과거 운행으로 나누어 관리 |
| 장소 이름·좌표·연결 | 암호화 저장 | 장소 이름에 주소를 쓰면 그 문자열은 저장됨. 좌표도 정확한 위치정보 |
| 검색 주소 | 현재 화면의 임시 검색 상태, 저장 JSON 주소 필드 제외 | 검색 제공자에 이미 보낸 검색어까지 지워지는 것은 아님 |
| GPS 표본 | 도착 판정용 메모리 | 지속 경로 파일 저장은 제거했지만 위치 권한과 GPS는 필요 |
| 운행 | 시작/종료·방향·대상 이름/좌표 스냅샷·도착 추정 시각 암호화 | 과거 기록 보존기한 자동 만료 없음. 종료 운행의 수동 삭제 가능 |
| 지도 | 로컬 HTML/Leaflet + 외부 OSM HTTPS 타일 | 서버가 조회 영역·IP 등을 알 수 있고 내부 WebView 캐시도 남을 수 있음 |
| XLSX | 사용자 선택 위치의 별도 파일 | 암호화되지 않음. 클라우드 저장 위치를 고르면 외부 전달 가능. 전체 복원 백업이 아님 |

주소 검색과 지도 그림은 외부 서비스를 사용하므로 **100% 오프라인/100% On-device 처리라고 말할 수 없습니다.** APK 서명키는 제작자 업데이트의 신원을 확인하는 키이고, 휴대폰 자료를 암호화하는 Keystore 키나 지도 서버의 TLS 인증서와는 별개입니다.

## 4. 보안 통제·점검 결과·보류 사유

- **저장:** AES-256-GCM, 새 12바이트 IV, 128비트 인증 태그·AAD, 프로세스 공용 잠금, AtomicFile·동기화·읽기 검증. 키 분실/변조 파일을 정상 빈 데이터로 대체하지 않음. 하드웨어 보호 수준은 기기별 미검증이며, 인증 필수 키·신뢰 카운터를 이용한 rollback 방어는 없음.
- **이관:** v1~v5의 주소·경로 필드를 v6에서 제외. legacy 평문은 암호화 이관/검증 성공 후 제거하며 실패 시 자료 보존을 위해 남을 수 있음. 주소 삭제는 외부 제공자·기존 엑셀·물리 저장 흔적 삭제를 의미하지 않음.
- **잠금·컴포넌트:** FLAG_SECURE, 백업/기기 이전 제외, 일반 운행 알림·immutable PendingIntent·비공개 서비스. 기기 잠금 해제 상태에서는 자동 진입하며 앱 독립 인증은 아님. 런처 MainActivity의 exported=true는 실행 기능 때문에 유지.
- **지도:** 번들 HTML/JS/CSS, CSP, HTTPS 호스트 제한, 혼합 콘텐츠 금지, 파일/content 접근·WebView 위치·JS 브리지 없음. 타일 캐시는 주 암호화 파일과 별개. 캐시를 무조건 끄는 변경은 제공자 정책·기능 영향 때문에 하지 않음. 인증서 고정은 없음.
- **내보내기:** 문자열 셀·XML escaping으로 이름의 수식 실행 방지, 취소 예외 유지·실패 문서 정리·공급자 오류 구분. 예기치 않은 공급자 오류에서도 정리해야 하므로 최종 포괄 예외 경계는 유지. 모든 공급자/전원 종료 조건에서 정리를 보장하지 않음.
- **Sparrow:** DNS 경고는 로컬 검증을 지적한 것으로 오탐 가능성이 높아 검증 코드를 유지. 솔트 없는 SHA-256은 비밀번호가 아닌 중복 이관 식별자라 호환성을 보존. 21건 검토와 별도 30건 기록을 섞어 “모두 수정”으로 세지 않음. 최신 재분석 미실행.
- **MobSF:** 과거 특정 APK 56/100, 사용자 과거 36/100은 비교 조건 불명. 코드/secrets/tracker 탐지 0은 부재의 증명이 아님. minSdk 경고는 이후 34로 정책 변경했으나 재점수화 안 함. DUMP 보호 receiver 및 native fortify 경고는 공격 성공 증거가 아님. API 감시 누락은 여전히 미완료.
- **TLS:** 기존 1.0.1-test에서 자체 서명·만료·다른 호스트명 복합 조건 각각 6연결 거부, 앱 요청 복호화 0바이트, 정상 복귀 확인. 다른 호스트명 조건은 신뢰 체인 오류가 먼저 확인되어 단독 검증은 미완료. 기기 전체 평문 GET 2건은 앱 귀속 미확인. 최신 1.0.2-test에 대한 재시험으로 표시하지 않음.

초기 보안 보고서의 R1~R10(디버그 배포, 열린 기기 접근, 키 인증, 평문 엑셀, 삭제/보존 차이, 이관 평문, rollback, GPS/시간 신뢰, 키 소실, 대량 자료/부분 출력)도 보존합니다. 현재 배포는 Debug가 아닌 Release이지만, 다른 위험이 그 이유만으로 해소되는 것은 아닙니다.

## 5. 검증 상태와 남은 운영 조건

최신 빌드·단위 테스트·린트·서명·APK 해시 결과는 [최종 배포 검증 기록](docs/FINAL-DELIVERY-2026-10-24.md)에 고정합니다. 과거 59건/21건/56점/TLS 결과를 이번 APK의 새 검사 결과로 재사용하지 않습니다. UI 테스트 컴파일과 기기에서 테스트 실행도 구분합니다.

운영 전 남은 항목:

1. 회사의 Android 14 이상 실기기에서 등록·핀 이동·재실행·삭제 확인/취소·XLSX 열기와 GPS 장시간 동작 검증.
2. 화면 잠금·절전·홈 이동·프로세스 종료·위치 권한 철회·오프라인·저장 공간 부족 시 복구 확인.

## 1. 먼저 알아둘 결론

**이 앱은 어르신 명단·승하차 좌표·운행 기록을 휴대폰 안에 암호화해 저장하는 On-device 앱입니다. 다만 주소 검색과 배경 지도는 외부 서비스를 이용하므로, 모든 기능이 휴대폰 안에서만 처리되는 완전한 오프라인 앱은 아닙니다.**

저장 파일을 보호하는 장치는 있지만, 모든 공격에 안전하다고 보증할 수는 없습니다. 특히 잠금이 풀린 휴대폰, 내보낸 엑셀, 지도 조회 흔적, 과거 기록에 남은 개인정보를 별도로 관리해야 합니다. 아래 '위험'은 실제 확인된 동작과 공격 가능성을 구분한 것으로, 모두 공격에 성공했다는 뜻은 아닙니다.

## 2. On-device 저장은 어떻게 이루어지나요?

앱이 사용하는 주 자료는 서버 데이터베이스나 휴대폰의 SQLite 데이터베이스가 아니라 **앱 전용 공간의 암호화 파일 하나(`care-v1.enc`)**에 저장됩니다. 다음 순서로 처리합니다.

1. 이름·좌표·운행 기록을 앱 내부의 구조화된 자료로 정리합니다.
2. 저장하면 안 되는 주소 필드를 빼고 자료가 올바른지 검사합니다.
3. 자료를 JSON이라는 데이터 형식으로 만든 뒤 메모리에서 암호화합니다. JSON 평문 파일을 따로 저장하는 방식은 아닙니다.
4. 암호화된 결과를 휴대폰의 앱 전용·백업 제외 공간에 씁니다.
5. 다시 읽어 원래 저장하려던 자료와 같은지 확인합니다.

화면에 표시할 때는 반대로 파일을 읽고 복호화합니다. 따라서 **저장 중 암호화**와 **앱을 사용 중인 메모리까지 항상 암호화**는 다릅니다. 화면 표시·검색·엑셀 작성 중에는 읽을 수 있는 이름과 좌표가 메모리에 존재합니다.

일반 앱은 Android가 제공하는 앱 간 격리로 이 전용 공간에 직접 접근하기 어렵습니다. 그러나 운영체제 보호를 해제한 기기(루팅), 앱 내부 실행 권한을 얻은 공격자, 개발·분석 권한을 가진 환경까지 같은 수준으로 방어한다고 볼 수는 없습니다.

## 4. 암호화와 저장 실패 보호

암호화는 **AES-256-GCM**을 사용합니다. 자료를 알아보기 어렵게 바꾸는 동시에 암호문이 변조됐는지도 검사하는 방식입니다. 같은 내용을 다시 저장해도 다른 암호문이 나오도록 매번 새 초기값(IV)을 사용합니다.

암호화 키는 소스 코드나 설정 파일에 고정 문자열로 넣지 않고 **Android Keystore**에서 만들고 관리합니다. 이를 '휴대폰 운영체제가 관리하는 열쇠 보관소'로 이해하면 됩니다. 모든 기기에서 별도 보안 하드웨어가 키를 보호하는지까지 확인한 것은 아닙니다.

쓰기 도중 실패했을 때 이전 자료를 보존하려고 AtomicFile을 사용하고, 저장 작업끼리 동시에 충돌하지 않도록 잠금을 둡니다. 파일이나 키가 잘못됐을 때 조용히 빈 명단으로 대체하지 않도록 작성되어 있습니다. 다만 전원 차단·저장장치 고장·복구 중 추가 오류까지 자료 보존을 절대 보장하지는 않습니다.

앱 자동 백업과 기기 간 이전을 제외하는 설정이 있습니다. 이는 무단 복사를 줄이는 데 도움이 되지만, **휴대폰 분실·앱 삭제·데이터 초기화·키 분실 시 복구하기 어려운 대가**가 있습니다. 엑셀은 운행 내역 출력물이며 앱 전체를 복원할 수 있는 백업 파일이 아닙니다.

구형 앱의 평문 설정 자료가 남아 있으면 암호화 이관과 재확인을 마친 뒤 지웁니다. 이관 실패 시에는 자료 유실을 막기 위해 원본을 남기므로, 구형 자료가 있던 기기에서는 이관 성공 여부도 중요합니다. 삭제 후 저장장치의 물리적 흔적까지 완전히 없앴다는 보장은 없습니다.

## 5. 휴대폰 밖으로 나가는 정보

### 주소 검색

주소 검색창의 입력값을 Android Geocoder에 전달합니다. 기기에 연결된 검색 제공자가 외부 서비스를 이용할 수 있습니다. 코드에서 어르신 명단 전체를 함께 보내는 동작은 찾지 못했습니다. 하지만 사용자가 검색창에 어르신 이름이나 집 주소를 입력하면 그 입력값은 검색 서비스로 전달될 수 있습니다.

### OSM 지도

지도 조작 프로그램(HTML·JavaScript·Leaflet)은 앱에 포함되어 있습니다. 배경 그림은 OpenStreetMap의 타일 서버에서 HTTPS로 받습니다. 타일은 큰 지도를 작은 사각형 그림으로 나눈 것으로, 요청 번호를 보면 어느 영역을 보고 있는지 추정할 수 있습니다.

타일 서버/CDN에는 요청 영역과 접속 IP, 앱·브라우저 정보 등이 전달될 수 있습니다. 현재 코드가 어르신 이름이나 전체 운행 자료를 지도 서버로 보내도록 작성된 것은 아닙니다. HTTPS도 **서비스 제공자에게 요청 내용을 숨겨 주는 기능은 아닙니다.**

코드는 파일 접근과 혼합 콘텐츠를 차단하고, 지도 리소스의 호스트를 제한합니다. 인증서 오류를 무시하거나 JavaScript에서 앱 기능을 직접 부르는 브리지를 등록하는 코드는 없습니다. 다만 리디렉션, 인증서 오류, WebView 버전별 동작을 공격 환경에서 모두 확인한 것은 아닙니다.

### 엑셀 저장

엑셀에는 선택한 종료 운행의 날짜·어르신 이름·등원 및 하원 시각을 기록하고, 좌표와 주소는 출력하지 않습니다. 이름을 엑셀 수식으로 실행하지 않도록 문자열 셀로 작성하고 특수문자를 처리합니다.

**XLSX 자체에는 암호가 걸려 있지 않습니다.** 클라우드 드라이브를 저장 위치로 선택하면 해당 제공자가 파일을 외부로 전송할 수 있고, 메신저로 보내면 수신자가 파일을 보관할 수 있습니다. 앱 내부 저장소의 암호화·백업 제외 설정은 내보낸 파일에 적용되지 않습니다.

## 7. 보안 도구의 경고는 어떻게 처리했나요?

Sparrow가 지적한 null 처리와 예외 처리를 보완했습니다. DNS 경고는 로컬 암호화·자료 검증을 지적한 사례가 있어 오탐 가능성이 높다고 판단했지만, 모든 상세 추적을 개별 검증한 것은 아닙니다. 검증 코드를 지워 경고만 숨기지는 않았습니다.

솔트 없는 SHA-256 경고의 해시는 비밀번호가 아니라 구형 자료의 중복 이관을 막는 표식입니다. 임의로 방식을 바꾸면 기존 자료와 비교가 깨질 수 있어 유지했습니다. 이것이 해시를 익명화 수단으로 인정한다는 뜻은 아닙니다. MainActivity의 exported=true도 정상 런처 실행에 필요해 유지했고, 위치 서비스는 외부 공개하지 않습니다.

이전 MobSF 점수는 분석용 Release APK에서 56/100이었으며, 사용자 측 예전 빌드의 36/100과 검사 조건이 같다고 확인되지 않았습니다. 점수는 보안 인증이나 안전 비율이 아닙니다. 현재 코드의 재분석 점수는 아직 없습니다.

## 좌표 중심 장소 저장 (v6)

주소 검색어와 검색 결과 주소는 등록 화면에서 지도 초기 위치를 찾는 임시 데이터입니다. 저장 시 장소 이름, 최종 위도·경도와 어르신 연결을 보관하고, 주소 문자열은 장소 및 운행 대상 스냅샷 JSON에 기록하지 않습니다. 저장 완료 후 등록 화면을 닫아 임시 검색 상태를 해제합니다. 수정 화면은 기존 좌표에서 시작하며 주소는 빈 검색창으로 표시됩니다.

기존 v1~v5 암호화 자료는 앱이 자료를 열 때 v6로 원자적으로 다시 저장하여 장소 및 과거 운행 대상의 주소 필드와 이동 경로 데이터를 제거합니다. 좌표가 없는 구형 장소는 추정 좌표를 만들지 않고 재지정 안내를 표시합니다. v6 저장 이후 구버전으로 되돌리면 자료를 읽을 수 없습니다. 기기에 이미 내보낸 파일이나 외부 검색 서비스에 전달된 검색어, 저장장치의 삭제 흔적에 대한 물리적 완전 삭제를 보장하지 않습니다.

좌표 역시 정확한 위치 정보입니다. 주소 검색 서비스 및 온라인 지도 타일 통신은 유지되므로 완전한 오프라인 앱은 아닙니다. 새 기기에 처음 설치하는 APK에는 테스트 중 기기에 입력한 자료가 포함되지 않습니다.

## 보안 종합 점검 보고서 (2026-10-21)

**판정: 주요 저장 보호와 검증은 구현되어 있으나, 모든 동적 과정에 보안 문제가 없다고 보증할 수 없다.** 온라인 지도/주소 검색의 외부 통신, 지도 캐시, 잠금 해제된 기기 접근, 평문 XLSX, 과거 기록 보존에 대한 잔여 위험이 있다. 이 문서는 코드 검토·자동 테스트·이전 MobSF 실행 증거를 구분하며 침투 테스트 완료나 보안 인증을 의미하지 않는다.

### 우선 해결·결정할 사항

1. **개인정보 접근·보존 정책:** 잠금 해제 기기에서 누구나 앱에 접근 가능한 현재 동작, 과거 운행 스냅샷 보존, 평문 내보내기를 운영자가 명시적으로 이해해야 한다. 독립 인증/자동 잠금/키 인증 연동은 백그라운드 운행 저장과 충돌할 수 있으므로 설계와 회귀 검증 후 변경해야 한다.
2. **지도 캐시와 통신:** 타일 캐시 잔존을 해결하려면 암호화 캐시/적합한 제공자/오프라인 지도 등을 설계 검토해야 한다. OSM 공용 타일 정책은 HTTP 캐시 준수를 요구하므로 캐시를 무조건 꺼서 매번 재다운로드하는 변경은 하지 않았다. [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/), [OSMF 개인정보 정책](https://osmfoundation.org/wiki/Privacy_Policy).
3. **WebView 경계 실증:** `shouldInterceptRequest`는 리디렉션의 최초 URL에만 호출될 수 있어 콜백만으로 모든 최종 목적지가 통제된다고 주장할 수 없다. 현재 CSP도 함께 작동하지만 우회·리디렉션·인증서 오류를 실제 WebView 버전별로 검사해야 한다. `unsafe-inline` CSP 및 경로/포트 제한의 강화도 기능 검증 후 검토한다. [Android WebViewClient](https://developer.android.com/reference/android/webkit/WebViewClient).
4. **런타임/네트워크 추가 검사:** TLS/MITM·인증서 오류 거부·앱별 트래픽 분리·Geocoder 실제 목적지·메모리/로그·키 접근·GPS 권한 철회·장시간 백그라운드 동작을 미완료 항목으로 남긴다. 이전 MobSF API 감시 기록은 비어 있었으며 이번 검토로 해결됐다고 볼 수 없다.
5. **가용성과 공급망:** 이름/데이터 전체 크기의 명시적 상한이 없어 대량 자료에서 메모리/저장 실패 가능성이 있다. 구형 Geocoder worker의 중단 불가 호출/대기열도 부하 테스트 필요. 검사 당시 Android 7 최소 지원(2026-10-23부터 Android 14로 상향), 구형 의존성, 번들 Leaflet/WebView 공급망의 전수 CVE 검사는 미완료다. 도구의 업데이트 권고가 현재 최신 버전 확정이나 취약점 입증을 뜻하지는 않는다.
