# 안심 동행 데이터 저장·보안 설명 보고서

작성일: 2026-10-23 · 대상: ee7a5ae의 앱 기능과 이번 커밋의 Android 14 최소 지원 변경

## 1. 먼저 알아둘 결론

**이 앱은 어르신 명단·승하차 좌표·운행 기록을 휴대폰 안에 암호화해 저장하는 On-device 앱입니다. 다만 주소 검색과 배경 지도는 외부 서비스를 이용하므로, 모든 기능이 휴대폰 안에서만 처리되는 완전한 오프라인 앱은 아닙니다.**

저장 파일을 보호하는 장치는 있지만, 모든 공격에 안전하다고 보증할 수는 없습니다. 특히 잠금이 풀린 휴대폰, 내보낸 엑셀, 지도 조회 흔적, 과거 기록에 남은 개인정보를 별도로 관리해야 합니다. 아래 '위험'은 실제 확인된 동작과 공격 가능성을 구분한 것으로, 모두 공격에 성공했다는 뜻은 아닙니다.

## 2. On-device 저장은 어떻게 이루어지나요?

앱이 사용하는 주 자료는 서버 데이터베이스나 휴대폰의 SQLite 데이터베이스가 아니라 **앱 전용 공간의 암호화 파일 하나(`care-v1.enc`)**에 저장됩니다. 다음 순서로 처리합니다.

1. 이름·좌표·운행 기록을 앱 내부의 구조화된 자료로 정리합니다.
2. 저장하면 안 되는 주소 필드를 빼고 자료가 올바른지 검사합니다.
3. 자료를 JSON이라는 데이터 형식으로 만든 뒤 메모리에서 암호화합니다. JSON 평문 파일을 따로 저장하는 방식은 아닙니다.
4. 암호화된 결과를 휴대폰의 앱 전용·백업 제외 공간에 씁니다.
5. 다시 읽어 원래 저장하려던 자료와 같은지 확인합니다.

화면에 표시할 때는 반대로 파일을 읽고 복호화합니다. 따라서 **저장 중 암호화**와 **앱을 사용 중인 메모리까지 항상 암호화**는 다릅니다. 화면 표시·검색·엑셀 작성 중에는 읽을 수 있는 이름과 좌표가 메모리에 존재합니다.

일반 앱은 Android가 제공하는 앱 간 격리로 이 전용 공간에 직접 접근하기 어렵습니다. 그러나 운영체제 보호를 해제한 기기(루팅), 앱 내부 실행 권한을 얻은 공격자, 개발·분석 권한을 가진 환경까지 같은 수준으로 방어한다고 볼 수는 없습니다.

## 3. 무엇을 저장하고, 무엇을 저장하지 않나요?

| --- | --- | --- |
| 어르신 이름 | 내부 식별번호와 함께 암호화 저장 | 이름은 익명화되지 않습니다. 앱에서 읽을 때 원래 이름으로 복원됩니다. |
| 승하차 장소 | 장소 이름, 위도·경도, 어르신과의 연결을 암호화 저장 | 좌표만으로도 위치를 알아낼 수 있어 민감정보로 취급해야 합니다. |
| 검색한 주소 | 현재 등록 화면에서 위치를 찾는 임시 자료로 사용하며 새 저장 JSON의 주소 필드에서는 제외 | 외부 검색 서비스에 이미 전달된 검색어까지 삭제되는 것은 아닙니다. 장소 이름 칸에 주소를 적으면 그 내용은 이름으로 저장됩니다. |

| 지도 그림·조회 흔적 | WebView라는 앱 내부 지도 표시 기능의 캐시에 남을 수 있음 | 주 자료 파일과 별개입니다. 지도 캐시까지 같은 AES 암호화로 보호하는 구현은 없습니다. |
| 내보낸 엑셀 | 사용자가 선택한 저장 위치에 별도 XLSX 파일 생성 | 앱 내부 암호화 보호를 벗어난 파일입니다. |

## 4. 암호화와 저장 실패 보호

암호화는 **AES-256-GCM**을 사용합니다. 자료를 알아보기 어렵게 바꾸는 동시에 암호문이 변조됐는지도 검사하는 방식입니다. 같은 내용을 다시 저장해도 다른 암호문이 나오도록 매번 새 초기값(IV)을 사용합니다.

암호화 키는 소스 코드나 설정 파일에 고정 문자열로 넣지 않고 **Android Keystore**에서 만들고 관리합니다. 이를 '휴대폰 운영체제가 관리하는 열쇠 보관소'로 이해하면 됩니다. 모든 기기에서 별도 보안 하드웨어가 키를 보호하는지까지 확인한 것은 아닙니다.

쓰기 도중 실패했을 때 이전 자료를 보존하려고 AtomicFile을 사용하고, 저장 작업끼리 동시에 충돌하지 않도록 잠금을 둡니다. 파일이나 키가 잘못됐을 때 조용히 빈 명단으로 대체하지 않도록 작성되어 있습니다. 다만 전원 차단·저장장치 고장·복구 중 추가 오류까지 자료 보존을 절대 보장하지는 않습니다.

앱 자동 백업과 기기 간 이전을 제외하는 설정이 있습니다. 이는 무단 복사를 줄이는 데 도움이 되지만, **휴대폰 분실·앱 삭제·데이터 초기화·키 분실 시 복구하기 어려운 대가**가 있습니다. 엑셀은 운행 내역 출력물이며 앱 전체를 복원할 수 있는 백업 파일이 아닙니다.

구형 앱의 평문 설정 자료가 남아 있으면 암호화 이관과 재확인을 마친 뒤 지웁니다. 이관 실패 시에는 자료 유실을 막기 위해 원본을 남기므로, 구형 자료가 있던 기기에서는 이관 성공 여부도 중요합니다. 삭제 후 저장장치의 물리적 흔적까지 완전히 없앴다는 보장은 없습니다.

## 5. 휴대폰 밖으로 나가는 정보

### 주소 검색

주소 검색창의 입력값을 Android Geocoder에 전달합니다. 기기에 연결된 검색 제공자가 외부 서비스를 이용할 수 있습니다. 코드에서 어르신 명단 전체를 함께 보내는 동작은 찾지 못했습니다. 하지만 사용자가 검색창에 어르신 이름이나 집 주소를 입력하면 그 입력값은 검색 서비스로 전달될 수 있습니다.

### OSM 지도

지도 조작 프로그램(HTML·JavaScript·Leaflet)은 앱에 포함되어 있습니다. 배경 그림은 OpenStreetMap의 타일 서버에서 HTTPS로 받습니다. 타일은 큰 지도를 작은 사각형 그림으로 나눈 것으로, 요청 번호를 보면 어느 영역을 보고 있는지 추정할 수 있습니다.

타일 서버/CDN에는 요청 영역과 접속 IP, 앱·브라우저 정보 등이 전달될 수 있습니다. 현재 코드가 어르신 이름이나 전체 운행 자료를 지도 서버로 보내도록 작성된 것은 아닙니다. HTTPS도 **서비스 제공자에게 요청 내용을 숨겨 주는 기능은 아닙니다.**

코드는 파일 접근과 혼합 콘텐츠를 차단하고, 지도 리소스의 호스트를 제한합니다. 인증서 오류를 무시하거나 JavaScript에서 앱 기능을 직접 부르는 브리지를 등록하는 코드는 없습니다. 다만 리디렉션, 인증서 오류, WebView 버전별 동작을 공격 환경에서 모두 확인한 것은 아닙니다.

### 엑셀 저장

엑셀에는 선택한 종료 운행의 날짜·어르신 이름·등원 및 하원 시각을 기록하고, 좌표와 주소는 출력하지 않습니다. 이름을 엑셀 수식으로 실행하지 않도록 문자열 셀로 작성하고 특수문자를 처리합니다.

**XLSX 자체에는 암호가 걸려 있지 않습니다.** 클라우드 드라이브를 저장 위치로 선택하면 해당 제공자가 파일을 외부로 전송할 수 있고, 메신저로 보내면 수신자가 파일을 보관할 수 있습니다. 앱 내부 저장소의 암호화·백업 제외 설정은 내보낸 파일에 적용되지 않습니다.

## 7. 보안 도구의 경고는 어떻게 처리했나요?

Sparrow가 지적한 null 처리와 예외 처리를 보완했습니다. DNS 경고는 로컬 암호화·자료 검증을 지적한 사례가 있어 오탐 가능성이 높다고 판단했지만, 모든 상세 추적을 개별 검증한 것은 아닙니다. 검증 코드를 지워 경고만 숨기지는 않았습니다.

솔트 없는 SHA-256 경고의 해시는 비밀번호가 아니라 구형 자료의 중복 이관을 막는 표식입니다. 임의로 방식을 바꾸면 기존 자료와 비교가 깨질 수 있어 유지했습니다. 이것이 해시를 익명화 수단으로 인정한다는 뜻은 아닙니다. MainActivity의 exported=true도 정상 런처 실행에 필요해 유지했고, 위치 서비스는 외부 공개하지 않습니다.

이전 MobSF 점수는 분석용 Release APK에서 56/100이었으며, 사용자 측 예전 빌드의 36/100과 검사 조건이 같다고 확인되지 않았습니다. 점수는 보안 인증이나 안전 비율이 아닙니다. 현재 코드의 재분석 점수는 아직 없습니다.

## 9. 앞으로 점검할 순서

1. Android 14 이상 실제 기기에서 등록·재실행·운행·잠금·권한 철회·엑셀 저장/취소를 다시 확인합니다.
2. 기기 잠금 정책과 앱 인증 필요성, 과거 자료의 보존 기간·삭제 범위를 정합니다. 인증을 강화할 때 백그라운드 운행 저장이 막히지 않도록 검증합니다.
3. 지도 통신 목적지와 인증서 오류·리디렉션을 관찰하고, 캐시 보호와 지도 제공 정책을 함께 검토합니다. 캐시를 무조건 끄는 방식은 OSM 이용 정책과 충돌할 수 있습니다.
4. 운영 배포 서명 APK를 기준으로 정적·동적 검사를 다시 하고, OS·WebView·의존성 보안 업데이트를 관리합니다.

이 보고서와 코드는 Git에 보관하지만 APK 릴리스를 새로 게시하는 작업은 별개입니다. 실제 이름·좌표 자료, 비밀키, 원본 기기 로그는 이 문서에 포함하지 않았습니다.
