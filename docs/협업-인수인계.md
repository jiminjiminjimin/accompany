# 안심 동행 프로젝트 협업 인수인계

작성 기준: 2026-10-18 / 프로젝트: `C:\AndroidSave` / 앱 패키지: `com.example.pathreport`

## 1. 처음 읽는 협업자를 위한 요약

노인 주간보호센터 차량의 등원·하원 과정에서, 등록 장소에 20초 이상 정차하면 어르신별 도착 시각을 자동 기록하는 Android 앱을 개발하고 있다. GPS 기록은 실제 승하차 확인이 아닌 **위치 기반 추정**이다.

현재는 **1단계인 장소·어르신 관리와 안전한 저장 기능을 구현한 상태**다. GPS 정차 자동 기록, 운행 관리, 기록 조회·수정 이력, 엑셀 내보내기는 아직 없다.

디버그 APK 빌드와 로컬 테스트는 성공했다. **Android Keystore를 포함한 기기 계측 테스트와 실제 화면 동작은 아직 검증하지 못했다.** 구현 완료와 기기 검증 완료를 구분해서 인계해야 한다.

다음 협업자는 먼저 기기 테스트를 실행하고 관리 화면·잠금·이전 동작을 확인하는 것이 우선이다. 그다음 운행 모델과 정차 판정 설계를 진행한다.

화면과 저장소 사이에 별도 ViewModel/Repository 계층은 아직 없다. `CareApp`에서 저장소를 호출하고, 파일 IO는 IO 디스패처에서 실행한다. 현재 데이터는 전체 스냅샷으로 암호화 저장한다. 향후 운행 기록이 누적될 때는 저장량과 쓰기 빈도를 검토해야 한다.

## 4. 데이터 구조와 지켜야 할 규칙

```text
CareData (schema version 1)
 ├─ places: StopPlace(id, name, address, latitude?, longitude?)
 ├─ elders: Elder(id, name)
 ├─ links: PlaceElder(placeId, elderId)
 └─ legacyDigest: 기존 원본의 SHA-256 또는 null

StopPlace 1 ── N PlaceElder N ── 1 Elder
```

- 수정 시 UUID를 바꾸지 않는다. 이름·주소를 ID로 사용하지 않는다.
- 동명이인을 자동 병합하지 않는다.
- 장소 삭제 시 해당 연결만 제거하고 어르신은 유지한다. 어르신 삭제 시 장소도 유지한다.
- 중복 ID, 중복 연결, 없는 ID에 대한 연결을 거부한다.
- 좌표는 유한한 숫자이고 위도 -90~90, 경도 -180~180이어야 한다.
- 새 장소의 저장은 이름·주소·좌표가 모두 있어야 가능하다. 기존 자료 이전으로 만들어진 장소만 좌표 미등록 상태를 허용하고 화면에서 보완을 안내한다.
- 주소를 바꾸면 이전 좌표를 비운다. 주소 검색 결과가 나와도 사용자가 선택하기 전에는 좌표를 확정하지 않는다.

## 5. 암호화 저장과 기존 데이터 이전

현재 Room은 사용하지 않는다. Room 자체가 암호화를 제공한다고 가정해서는 안 된다.

운영 파일은 `context.noBackupFilesDir/care-v1.enc`, Keystore 별칭은 `care-data-v1`이다. 파일 형식은 `CAR1 헤더 + 12바이트 IV + 암호문/인증 태그`이며 AAD는 `care-schema-1`이다. 저장마다 새 IV를 사용한다. 파일 작성과 sync, AtomicFile 교체 후 다시 복호화해 저장 모델과 일치하는지 확인한다. 여러 저장소 인스턴스의 접근은 프로세스 내 공통 잠금으로 직렬화한다.

키를 파일이나 SharedPreferences에 저장하지 않는다. 기존 암호문이 있는데 키가 사라졌으면 새 키로 덮어쓰지 않는다. 앱 진입 인증과 저장 키 관리는 별도다. 키 매 사용에 기기 인증을 요구하지는 않는다.

기존 저장소는 SharedPreferences `pathreport`의 문자열 키 `places`이며, 내용은 `[{"name":"...","address":"..."}]`다.

이전 순서:

1. 원본을 파싱·검증한다. 잘못된 자료를 빈 목록으로 대체하지 않는다.
2. 같은 주소는 하나의 `이전 장소 N`으로 묶고, 각 기존 항목은 별도 어르신으로 연결한다. 좌표는 임의 추정하지 않는다.
3. 변환 자료와 원본 digest를 하나의 암호화 파일로 저장한다.
4. 다시 읽어 전체 모델 일치를 확인한다.
5. 성공한 뒤에만 `places` 키를 동기 commit으로 제거한다.

암호문 저장 후 평문 삭제 전에 종료됐으면 digest로 이미 이전한 사실을 판단해 중복 삽입 없이 삭제를 재시도한다. 원본이 예상과 다르게 바뀌었거나 손상·쓰기 실패가 있으면 평문을 보존하고 접근을 중단한다. 실패 시 앱 데이터를 초기화하는 해결법을 넣지 않는다.

## 6. 개인정보와 외부 통신 원칙

- Firebase, 분석 SDK, 서버 동기화를 추가하지 않는다.
- 주소 검색에만 주소 문자열을 외부로 전달할 수 있다. 이름·장소명·저장 데이터 전체를 검색 요청에 포함하지 않는다.
- Geocoder를 사용하므로 현재 별도 서비스 가입·API 키·유료 계약은 없다. 제공자는 기기에 따라 다르다. 검색 실패·빈 결과·네트워크 실패·미지원·15초 제한 안내를 구현했다.
- GPS 등록은 한 위치를 받은 뒤 해제하고, 25초 제한과 취소 처리를 둔다. 역지오코딩으로 좌표를 외부에 보내지 않는다. 전체 이동 경로는 저장하지 않는다.
- 로그·오류 메시지·향후 운행 알림에 이름·주소를 넣지 않는다.
- 민감 저장 영역을 백업과 기기 이전에서 제외한다. 앱 삭제·데이터 초기화 후 복구를 전제로 설계하지 않는다.
- 앱 잠금 해제는 기기 PIN·패턴·비밀번호 확인을 거친다. 기기 잠금이 없으면 관리 화면 접근을 막는다.
- 개발·시연·테스트는 가상 데이터로 한다. 다른 협업자에게 실제 어르신 정보나 운영 저장 파일을 전달하지 않는다.
- 신규 서비스 가입·유료 API가 필요해지면 도입 전에 이유와 대안을 사용자에게 설명한다.

프로젝트 루트 PowerShell에서 실행한다.

```powershell
# 기존 환경으로 디버그 빌드
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-debug.ps1 -Offline -NoDaemon -NoConfigurationCache

# 로컬 테스트와 계측 테스트 APK 생성
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\verify-phase1.ps1

# 기기 연결 후 계측 테스트 (필요 도구 캐시가 없는 환경은 -Online 추가)
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\verify-phase1.ps1 -Connected

# Lint 도구 다운로드를 허용하는 환경
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\verify-phase1.ps1 -Lint -Online
```

오프라인 캐시는 기기마다 다르므로 새 PC에서 첫 빌드 성공을 보장하지 않는다. `build-debug.ps1`은 `-Offline` 없이 실행할 수도 있다. 의존성이 없다는 이유만으로 버전을 바꾸지 말고 해당 도구를 받을 수 있는 정상 네트워크에서 준비한다. ExecutionPolicy 옵션은 실행 프로세스에만 적용한다.

| 5 | 운행 서비스·한국어 화면 | 화면 꺼짐 중 동작, 운행 종료 시 요청 해제, 권한 회수·재시작 대응, 알림에 개인정보 없음 |
| 6 | 기록 관리·엑셀 | 조회·수정 이력 보존, 내보내기 직전 기기 인증, 실제 .xlsx 생성·검증 |

거리 반경과 허용 GPS 정확도, 같은 운행에서 필요한 기록 종류, 여러 장소에 같은 어르신이 연결됐을 때 처리 정책은 아직 확정되지 않았다. 임의 확정된 요구사항처럼 문서화하지 말고 구현 전에 결정한다.

위치 요청 중 저장 전 확인을 열었을 때의 일관성, lifecycle 전환 시 요청 해제, 미저장 입력 소실 안내 등은 **추가 점검 후보**이며 현재 재현·확정된 결함 목록은 아니다.

## 10. 두 사람이 나눠 작업하는 방법 제안

담당자는 아직 정하지 않았다. 아래는 충돌을 줄이기 위한 제안이다.

| 담당 제안 | 작업 영역 | 주요 파일 |
| --- | --- | --- |
| 협업자 A | 기기 검증, 관리 화면 개선, 한국어 안내 | MainActivity.kt, 계측 테스트, 확인 절차 문서 |
| 협업자 B | 운행 모델·정차 판정의 순수 로직과 테스트 | 새 운행/정차 로직 파일, 로컬 테스트 |
| 공동 검토 | 저장 스키마 변경, 키 관리, 권한/서비스 추가 | CareData.kt, SecureCareStore.kt, AndroidManifest.xml |

공통 파일을 수정하기 전 변경 범위를 공유한다. 운행 기능은 우선 새 파일로 분리하고, 관리 화면과 저장 형식에 연결할 때 함께 검토한다. 스키마·암호화 형식 변경은 기존 자료를 여는 이전 경로와 테스트를 함께 제공한다.

이번 인계에서 Git 상태나 커밋 기반 버전은 확인하지 않았다. 인수 시 저장소 상태부터 확인하고 각자의 변경을 구분한다. 기존 코드 참고본은 `docs/original-phase1/`에 있지만 완전한 Git 이력이나 전체 프로젝트 백업은 아니다.

다른 PC로 공유할 때는 소스·Gradle Wrapper·버전 카탈로그·스크립트·문서를 중심으로 전달한다. `.gradle`, `.gradle-user-home`, `.kotlin`, `build`, `app/build`는 재생성 가능한 캐시/산출물이다. `local.properties`의 SDK 경로는 각 PC에 맞춰 설정한다. 기존 운영 기기 업데이트가 필요하다면 서명 연속성을 먼저 확인하고, 설치된 앱을 지우지 않는다.
