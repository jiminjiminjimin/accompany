# MVP 2차 개발 — 화면이 열린 동안의 GPS 도착 추정

기준일: 2026-10-18. 1차의 운행 관리 위에 GPS 정차 판정·자동 저장·기록 조회를 추가했다.

## 구현과 초기 판정 기준

- 진행 중인 운행의 시작 당시 대상·장소 스냅샷을 기준으로 판단한다.
- 장소 반경 50m, 수평 위치 정확도 30m 이하인 새 GPS 표본을 사용한다.
- 연속 20초 정차를 확인한다. 속도가 제공되면 1.5m/s 이하여야 하고, 정차 시작 좌표에서 10m 넘게 벗어나면 시간을 다시 센다. 이 수치는 현장 검증 전의 초기 MVP 값이며 StopPolicy에서 관리한다.
- GPS 표본 간격이나 표본 나이가 5초를 넘으면 연속 정차를 이어 붙이지 않는다. 같은/과거 시각의 재전송 표본은 시간을 진행시키지 않는다. 타이머만으로 도착을 확정하지 않는다.
- 시간 판정은 GPS의 부팅 후 단조 증가 시간(elapsedRealtimeNanos)을 사용한다. 기록은 정차 시작 시각과 확인 시각을 저장한다. 기기 시계 변경으로 확인 시간이 역전되지 않도록 확인 시각은 시작 시각과 단조 시간 차이로 계산한다.
- 같은 장소에 여러 운행 대상이 연결되면 한 번의 정차 확인으로 각 대상의 도착을 기록한다. 운행당 어르신별 도착 추정은 하나이며 재방문·재실행으로 중복되지 않는다.
- 저장 전에는 완료 인원을 늘리지 않는다. 저장 대기 기록은 메모리에서 유지하며 실패 시 약 5초 간격으로 재시도한다. 종료할 때 화면에 있는 대기 기록도 함께 저장한다. 저장 완료 전에 앱 프로세스가 종료되면 메모리의 대기 기록은 보장되지 않는다.
- 자동 기록과 관리 화면 저장은 같은 저장 경로에서 직렬 처리한다. 저장 직전의 최신 자료에 변경을 적용하여 관리 화면의 이전 스냅샷으로 새 도착 기록을 덮어쓰지 않는다.

## 감지 범위와 화면

운행이 있고 정확한 위치 권한이 허용돼 있으면 잠금 해제된 앱이 RESUMED 상태일 때 GPS를 구독한다. 앱 탭을 바꾸어도 유지한다. 앱 이탈, 잠금, 화면 꺼짐, 회전 시 구독을 해제하며 미완료 정차 시간을 초기화한다. 복귀 후 새 표본으로 다시 확인한다. 운행 종료 또는 모든 대상 기록 완료 시 GPS를 해제한다.

운행 화면에 위치 권한 안내, GPS 꺼짐/수신 대기/오차/정차 진행 상태, 저장 대기 인원, 기록 완료·미기록 인원을 표시한다. 운행 상세는 어르신별 도착 추정 시각 또는 미기록 상태를 보여준다. 실제 승하차 확인이라는 표현은 사용하지 않는다.

이번 단계에는 foreground service가 없으므로 화면 꺼짐 중 운행 감지는 아직 지원하지 않는다. 전체 이동 경로와 원시 위치 표본은 파일에 저장하지 않는다.

## 저장 호환성

CareData JSON version 3. 각 Trip에 arrivals(어르신 ID, 장소 ID, 추정 시각, 확인 시각, 출처)를 추가했다. version 1/2를 그대로 읽고 다음 저장 때 version 3을 쓴다. version 3에서는 arrivals 필드가 없거나 중복/잘못된 참조/유효하지 않은 시각이면 거부한다. 기존 파일·키·CAR1 암호화 봉투·AAD는 유지한다. 구버전 앱으로의 역이전은 지원하지 않는다.

## Android Studio에서 직접 확인하기

1. 가상 어르신을 추가하고 장소에 연결한다. 장소 좌표를 위도 **37.5**, 경도 **127.0**으로 등록한다.
2. 운행 탭에서 등원/하원, 어르신과 장소를 선택하고 시작한다.
3. 정확한 위치 권한을 허용하고 기기의 위치 설정을 켠다. 권한 창으로 앱이 잠기면 다시 인증한다.
4. 앱을 운행 화면에 둔다. 에뮬레이터 Extended controls → Location에서 가상 위치를 지정하거나 아래 스크립트로 같은 위치를 반복 전송한다. 화면에는 GPS 수신·정차 진행 상태가 보여야 한다.
5. 20초를 충족한 뒤 기록 완료 인원이 늘고 상세에 도착 추정 시각이 나타나는지 확인한다.
6. 같은 위치를 다시 보내도 기록이 늘지 않는지 확인한다.
7. 운행 종료 후 목록에서 기록을 확인한다. 앱을 재실행해도 저장된 도착 기록이 남아야 한다.

프로젝트 루트의 Android Studio PowerShell 터미널에서:

```powershell
# 한 장소에서 25초 정차. 실제 기기는 허용하지 않는 에뮬레이터 전용 스크립트다.
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\simulate-gps.ps1 -Latitude 37.5 -Longitude 127.0 -Seconds 25
```

여러 에뮬레이터가 있으면 `-Serial emulator-5556`처럼 장치 번호를 지정한다. SDK 경로가 다르면 `-AdbPath '실제 SDK 경로\platform-tools\adb.exe'`를 지정한다. 스크립트가 종료돼도 에뮬레이터가 마지막 위치를 계속 보고할 수 있으므로, 수신 중단 검사는 GPS 설정을 끄거나 앱을 벗어나서 확인한다.

다음 검사는 각각 새 운행에서 진행한다.

| 검사 | 방법 | 기대 결과 |
| --- | --- | --- |
| 짧은 정차 후 이탈 | 37.5/127.0에 10초 전송 후 37.501/127.0으로 이동 | 기록 없음, 재진입 후 새로 20초 확인 |
| 여러 어르신 | 같은 장소에 두 어르신을 선택 | 두 사람 모두 한 번씩 기록 |
| GPS 꺼짐 | 정차 확인 도중 기기 위치 설정 끄기 | 판정 중지, 켠 뒤 새로 확인 |
| 화면 이탈 | 정차 10초 후 홈 이동, 다시 인증 | 이전 10초와 합산하지 않음 |
| 중복 방지 | 기록 완료 후 이탈·재방문 | 어르신당 기록 하나 |
| 종료 | 운행 종료 후 위치 반복 전송 | 기록 추가 없음 |

에뮬레이터 위치 기능: https://developer.android.com/studio/run/emulator-extended-controls
위치 수신 API: https://developer.android.com/reference/android/location/LocationManager

## 검증 결과

- assembleDebug, testDebugUnitTest, assembleDebugAndroidTest 성공.
- 로컬 테스트 총 24개 통과, 실패 0. 정차 판정 12개가 추가됐다.
- 20초 경계, 이탈/재진입, 위치 오차·NaN, 수신 공백·오래된 위치·미래 위치, 재전송 표본, 속도·좌표 이동, 작은 GPS 흔들림, 같은 장소 여러 명, 저장 재시도·중복, 앱 중단·시계 변경, 기록 무결성을 검증했다.
- v2 암호화 운행 파일의 읽기→v3 도착 추가→암호화 재열기 테스트를 추가해 컴파일했다. 이번 단계의 기기 실행 및 실제 GPS 수신·화면 검증은 사용자가 수행한다. 이전 단계의 기기 테스트 통과를 이번 버전의 통과로 간주하지 않는다.
- 기존 화면 테스트는 현재 에뮬레이터/Espresso의 InputManager 호환성 문제가 있었으므로 수동 확인 절차를 제공한다.
- Android Lint는 이번 단계에서 실행하지 않았다. Gradle/JDK/SDK와 앱 ID/서명 설정은 바꾸지 않았다.

## 주요 변경 파일

- StopDetector.kt: Android에 의존하지 않는 정차 판정, 도착 데이터, 중복 방지.
- TripTracking.kt: 앱 lifecycle에 맞춘 GPS 구독/해제, 상태, 저장 재시도.
- TripData.kt / TripCodec.kt / CareData.kt: 도착 기록 검증·직렬화와 v1/v2 호환성.
- MainActivity.kt / TripScreen.kt: 최신 자료 기준 저장, GPS 안내와 기록 조회.
- StopDetectorTest.kt / SecureCareStoreTest.kt: 정차·중복·저장 호환성 검증.
- simulate-gps.ps1: 에뮬레이터 가상 GPS 반복 전송.
