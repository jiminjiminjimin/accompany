# 이동 기록 지도 · 2026-10-19

## 사용 방법
1. Android Studio에서 기존 com.example.pathreport 앱을 Run하여 업데이트한다.
2. 등원/하원 운행을 시작하고 GPS 위치를 이동시킨다.
3. 운행 종료 후 운행 내역 → 운행 선택 → 이동 기록 지도 보기를 누른다.
4. 지도를 확대·축소하거나 시간 슬라이더로 기록된 위치를 확인한다.
5. 초록은 첫 기록, 빨강은 마지막 기록, 숫자는 운행 대상의 장소다. 장소를 누르면 대상 이름과 도착 추정 시각 또는 미기록 상태가 나온다.

## 기록과 지도
- 정확도 30m 이하, 수신 후 5초 이내인 위치를 약 5초 간격으로 기록한다.
- 기록 좌표·시각·정확도와 구간 분리 여부는 기존 AES-GCM 암호화 저장소에 저장한다.
- 도착 기록이 모두 완료되어도 명시적으로 운행 종료를 누를 때까지 경로를 기록한다.
- 30초 초과 수신 공백, 서비스 재개, GPS 중단, 초속 60m 초과로 좌표가 튀는 구간은 선으로 연결하거나 거리 합산하지 않는다.
- 거리 표시는 저장된 좌표 간 직선거리 합계의 근삿값이다. 도로 주행거리나 계기판 거리와 다를 수 있다.
- 최대 운행당 20,000개(5초 간격 약 27시간). 한도 도달 시 화면 안내하며 기존 점은 유지한다.
- 저장은 약 5초 간격으로 재시도 가능하게 처리하고, 운행 종료 시 대기 중인 경로와 도착 기록을 함께 저장한다.
- 프로세스 강제 종료/비정상 중단 시 아직 디스크에 저장되지 않은 최근 점은 유실될 수 있다. 정상 저장 중에는 보통 최근 약 5초이며 저장 실패가 지속되면 더 길 수 있다.
- 서비스는 강제 종료 후 자동 재시작하지 않는다. 앱에서 감지를 재개한다.
- 진행 중 운행의 지도는 열었을 때 저장된 경로의 스냅샷이다. 다시 열면 최신 저장 결과가 표시된다.
- 기존 운행이나 위치를 수신하지 못한 운행은 경로 없음 안내를 표시한다. 과거 경로를 추측해서 만들지 않는다.

## 저장 호환성과 외부 지도
- 자료 형식 v4. 기존 v1~v3는 경로가 없는 상태로 읽는다. 파일명, 암호화 키, 앱 ID는 유지한다.
- v4 자료를 저장한 후에는 v4 미지원 구버전 앱으로 되돌리지 않는다.
- Leaflet 1.9.4 JS/CSS/라이선스를 APK assets에 포함했다. 실행 시 외부 JavaScript를 받지 않는다.
- 지도 이동·확대는 로컬 WebView에서 처리한다. OpenStreetMap 표준 타일 서버에 표시 영역 타일만 HTTPS로 요청한다.
- 서버는 요청 IP와 타일 영역을 알 수 있다. 경로 목록·이름·주소를 업로드하는 API는 없다.
- WebView 파일/콘텐츠 접근과 위치 권한을 끄고 JavaScript 브리지 없이 로컬 라이브러리 및 지도 타일만 허용한다.
- 배경 지도는 인터넷이 필요하다. 네트워크 실패 안내와 다시 불러오기 버튼을 제공하며 로컬 경로 표시/시간 슬라이더는 유지한다.
- 출처 표기, 앱 식별 User-Agent 및 기본 HTTP 캐시를 사용한다. 배포 규모가 커지면 지도 공급자 용량·약관을 다시 검토한다.
- 이전 보안 보고서/단계 문서의 '이동 경로 미저장' 설명은 당시 구현 기준이다. 현재 구현은 이 문서와 README가 기준이다.
- 엑셀 내보내기에는 경로를 추가하지 않았다.

## 검증
- assembleDebug / testDebugUnitTest / assembleDebugAndroidTest 성공. 로컬 단위 테스트 54 개 통과, 실패 0 개, 오류 0 개.
- 좌표 품질·샘플 간격·수신 공백·GPS 좌표 급변·시계 보정·재시도 중복·종료 후 쓰기 차단·거리 계산 단위 테스트.
- v4 직렬화 왕복/v3 호환 및 지도 HTML 삽입 방지 기기 테스트 작성·컴파일. 기기에서 실행하지 않음.
- Android WebView에서 실제 타일 로딩, 확대/축소, 시간 슬라이더, 회전, 잠금 복귀 및 장시간 운행은 Android Studio/기기에서 확인 필요.
- 앱 설치·삭제·데이터 초기화를 실행하지 않음. 별도 테스트 앱을 설치하지 않음.
