# MVP 1차 개발 — 수동 운행 관리

기준일: 2026-10-18. 기존 인수인계 문서 이후에 추가된 기능이다.

## 구현 범위

- 기본 화면의 운행 탭에서 등원/하원, 대상 어르신, 어르신별 연결 장소 한 곳을 선택한다.
- 좌표가 있는 연결 장소만 선택 가능하다. 같은 이름도 ID로 구분한다.
- 진행 중인 운행은 한 개로 제한한다. 시작·종료 시각과 대상/장소 스냅샷을 암호화 저장한다.
- 앱 잠금/재실행 후에도 저장된 진행 상태와 내역을 조회한다. 종료는 명시적으로 수행한다.
- 장소/어르신 수정·삭제가 과거 또는 진행 중 운행의 스냅샷을 변경하지 않는다.
- 기록 시각은 기기 시각이다. 종료 시 시계가 과거로 바뀌었다면 시작 시각보다 이르게 저장하지 않는다.
- GPS 수집, 도착 자동 기록, 백그라운드 위치 서비스, 엑셀, 기록 수정은 이번 범위에 없다.

## 저장 호환성

CareData JSON은 version 2이며 trips를 추가했다. version 1도 읽고, 다음 저장 때 version 2로 기록한다. 기존 ID와 legacyDigest를 보존한다. 잘못된 운행이나 미지원 버전은 거부한다.

암호화 파일 경로 care-v1.enc, Keystore 별칭 care-data-v1, CAR1 봉투와 기존 AAD는 호환성을 위해 유지한다. JSON 버전과 암호화 봉투 버전은 별개다. 저장 후 재열기 비교와 AtomicFile 동작도 유지한다. 앱 삭제나 자료 초기화는 하지 않는다. 운행을 저장한 뒤 구버전 앱으로 되돌리는 기능은 지원하지 않는다.

## 코드

- TripData.kt: 운행·대상 스냅샷, 유효성 검사, 시작/종료 상태 전이.
- TripCodec.kt / CareData.kt: 운행 직렬화와 v1 읽기 호환성.
- TripScreen.kt / MainActivity.kt: 대상·장소 선택, 종료 확인, 목록·상세.
- TripDataTest.kt: 중복 운행, 잘못된 대상, 좌표 누락, 스냅샷 보존, 시계 변경 등.
- SecureCareStoreTest.kt: 실제 v1 암호화 파일의 읽기·저장·재열기 호환성 추가.
- TripScreenTest.kt: 대상 선택→시작→종료, 좌표 없는 대상의 선택 차단.

## 수동 확인

1. 가상 어르신을 등록하고 좌표가 있는 가상 장소에 연결한다.
2. 운행 탭에서 등원/하원과 대상·장소를 선택하고 시작한다.
3. 다른 운행을 동시에 시작할 수 없는지, 대상·장소 상세를 확인한다.
4. 앱 잠금·재실행 후 인증해 진행 상태를 확인한다.
5. 운행을 종료하고 목록에서 시작·종료 시각과 대상을 조회한다.
6. 관리 정보를 수정하거나 삭제한 후에도 운행 당시 스냅샷이 남는지 확인한다.
7. 저장 실패 때 성공 상태로 전환되지 않고 재시도할 수 있는지 확인한다.

## 검증

- 디버그 APK, 로컬 테스트, 계측 테스트 APK 빌드 성공.
- 로컬 테스트 12개 통과, 실패 0 (기존 8개 + 운행 4개).
- Gradle/JDK/SDK 버전 및 프로젝트의 앱 ID/서명 설정은 변경하지 않았다.
- Gradle 기기 실행은 UTP 도구 캐시 누락으로 실패했다. 직접 설치도 기존 에뮬레이터 앱과 서명이 달라 거부됐으며 기존 앱을 삭제하지 않았다.
- 기기 검증 결과는 아래에 별도로 기록한다.
- 별도 앱 ID com.example.pathreport.mvpverify의 임시 복사본으로 에뮬레이터에서 SecureCareStoreTest 8개 통과. 실제 Keystore, v1 암호문 읽기, v2 저장/재열기, 자료 보존을 확인했다.
- 기존 저장 테스트의 Context를 targetContext로 수정하고, 전용 noBackup 하위 폴더·별도 접두사의 SharedPreferences·테스트 전용 키로 운영 자료와 분리했다. 테스트 APK 자체 Context는 실행 프로세스 UID와 달라 파일 쓰기가 실패했다.
- 운행 화면 테스트 2개는 컴파일됐으나 에뮬레이터의 InputManager.getInstance와 Espresso 호환성 오류로 실행 실패했다. 화면 수동 검증은 사용자 Android Studio에서 진행한다. 앱의 UI 결함으로 확정한 결과는 아니다.
- 원본 프로젝트 앱 ID는 그대로 유지했다. 에뮬레이터의 기존 앱은 삭제하지 않았다. 임시 검증용 앱은 별도 ID로 설치돼 있다.
