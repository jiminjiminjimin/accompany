# APK 서명 충돌 예방과 데이터 손실 없는 대응

작성일: 2026-10-24. 대상: 직접 배포하는 안심 동행 `1.0.1-test` APK.

## 서명 충돌이란?

Android는 같은 패키지 이름의 앱을 업데이트할 때 서명 관계를 확인합니다. 다른 키로 서명된 APK가 기존 앱의 데이터에 접근하지 못하도록 설치를 막는 정상적인 보호입니다. APK 파일명을 바꿔서는 해결되지 않습니다. [Android 앱 서명 안내](https://developer.android.com/studio/publish/app-signing)

이번 APK의 패키지 이름은 `com.example.pathreport`, versionCode는 2입니다. 별도 테스트 키로 서명했습니다. Android Studio 기본 Run의 Debug 키, 과거 MobSF 분석용 임시 키와는 다릅니다. TLS 서버 인증서와 APK 서명 인증서는 서로 다른 용도입니다.

## 앞으로 충돌을 예방하는 방법

1. 이 테스트 앱의 후속 APK는 같은 테스트 키·같은 패키지 이름으로 만들고 versionCode를 올립니다.
2. 빌드 후 `apksigner verify --verbose --print-certs 파일.apk`로 서명과 인증서 SHA-256을 확인합니다. 현재 지문은 `a1665516f4b092c054480863e58457997f5534f7e26aa9c336370da588f2b85c`입니다. 이것은 APK 파일 자체의 SHA-256과 다릅니다.
3. 테스트 APK가 설치된 휴대폰에는 기본 Debug Run을 덮어쓰지 않습니다. 개발은 별도 에뮬레이터에서 진행합니다. 향후 Debug용 applicationIdSuffix를 도입하면 두 앱을 병행 설치할 수 있지만, 현재 코드에는 적용하지 않았고 데이터도 자동 공유되지 않습니다.
4. 정식 배포 전에는 앱 ID와 정식 서명 전략을 확정합니다. 새 키를 만들기만 하면 기존 사용자가 자동 업데이트되는 것은 아닙니다. Play App Signing을 쓰면 업로드 키와 실제 앱 서명키도 구분해야 합니다.

## 서명키 보관과 백업

제작 PC의 `%USERPROFILE%\.android\accompany-test-release\`에 다음 파일이 있습니다.

- `accompany-test.jks`: 개인 서명키. alias는 `accompany-test`.
- `password.dpapi`: 현재 Windows 사용자 환경에서 보호한 비밀번호.

이 파일은 GitHub, E:\DaycareApp 배포 폴더, 이메일 첨부에 넣지 않습니다. 디렉터리는 현재 사용자와 SYSTEM으로 접근 권한을 제한했습니다. **별도 장치의 안전한 백업은 아직 만들지 않았습니다.** PC 고장에 대비해 키는 접근이 제한된 암호화 백업에 보관하고, 비밀번호는 기관 승인 비밀번호 관리자 등에 별도로 보관해야 합니다.

DPAPI 파일을 다른 PC로 복사한다고 비밀번호가 복구되는 것은 아닙니다. Windows 사용자 환경 변경·재설치 전, 기존 PC에서 비밀번호 복구와 새 환경의 서명 검증을 확인해야 합니다. 비밀번호를 터미널 기록, Git, 보고서에 출력하지 않습니다. 새 키를 생성해서 기존 키를 덮어쓰지 않습니다.

## 설치가 거부될 때

| 상황 | 대응 |
| --- | --- |
| 이번이 첫 설치 | 기존 앱 서명 충돌 대상이 없습니다. Android 14 이상 및 기관 설치 정책을 확인합니다. |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 또는 서명 충돌 | 기존 앱을 유지하고 기존 APK와 새 APK의 인증서 지문을 비교합니다. 기존 서명키로 같은 최신 코드를 다시 빌드·서명하는 것이 우선입니다. |
| 기존 앱이 Android Studio Debug 앱 | 이번 테스트 Release와 다른 키입니다. 기존 자료가 필요하면 별도 기기로 테스트하거나, 개발 당시 Debug 키를 보유한 상태에서 데이터 보존 방안을 검토합니다. 운영용으로 Debug 키를 계속 쓰는 것은 권장하지 않습니다. |
| 버전 다운그레이드 오류 | 새 APK의 versionCode가 기존 설치보다 높은지 확인합니다. 서명 문제와 별개이며 강제 다운그레이드로 우회하지 않습니다. |
| 기존 키 분실 | 일반적인 같은 패키지 덮어쓰기 업데이트는 불가능합니다. 준비된 서명키 회전·플랫폼 복구 경로가 없는 현재 테스트 배포에서는 새 키만으로 복구할 수 없습니다. |
| 기기/기관 정책이 설치 차단 | MDM·보안 담당자에게 확인합니다. Play Protect나 기관 통제를 우회하지 않습니다. |

**기존 앱 삭제·앱 데이터 삭제는 마지막 선택입니다.** 이 앱은 내부 암호화 파일과 Android Keystore를 사용하므로 삭제하면 자료를 잃을 수 있습니다. 암호화 파일만 복사해도 다른 기기에서 복호화된다는 보장은 없습니다. 내보낸 엑셀은 전체 데이터 복원용 백업이 아니며, 현재 전체 복원 기능도 없습니다. 실제 자료가 있다면 삭제 전에 별도 보존 계획을 세워야 합니다.

자료가 없는 테스트 앱임을 사용자가 확인한 경우에만 기존 앱을 삭제하고 새로 설치할 수 있습니다. 이 절차는 데이터 이전이 아니라 초기화 후 신규 설치입니다.
