# 안심 동행

주간보호센터의 어르신·승하차장소를 관리하고, GPS를 이용해 등·하원 도착 시간을 추정하여 기록하는 Android 앱입니다.

## TLS 공격 검사 및 APK 서명 안내 · 2026-10-24

[TLS 중간자 공격 검사 보고서](TLS-TEST-2026-10-24.md)와 [요약 증거](TLS-EVIDENCE-2026-10-24.json)를 추가했습니다. 배포 APK를 Android 17/API 37 격리 에뮬레이터에서 검사하여 OSM 지도 연결의 자체 서명·만료·호스트명 불일치 복합 조건 거부와 정상 연결 복귀를 확인했습니다. 호스트명 단독 검사, Geocoder TLS, Android 14 실기기 및 신뢰 CA 공격은 미검증입니다. 전체 보안 인증을 의미하지 않습니다.

[APK 서명 충돌 예방·해결 안내](APK-SIGNING-RECOVERY.md)에 같은 키로 업데이트하는 방법, Debug 앱과의 충돌, 키 백업 한계 및 기존 데이터 손실을 피하는 대응을 정리했습니다. 이번 변경은 검사 결과와 안내 문서이며 배포 APK를 변경하지 않았습니다.

엑셀에는 날짜, 어르신 이름, 등원 시간, 하원 시간이 표시됩니다. **내보낸 XLSX는 암호화되지 않습니다.** 앱 내부 암호화 저장과 별개입니다.

GPS 기록은 실제 승하차 확인이 아닌 위치 기반 추정입니다. 등록 장소 반경 50m에서 연속 20초 정차하고 위치 오차가 30m 이하인 경우를 기준으로 하며, 수신 간격·속도·좌표 변화도 확인합니다. GPS 샘플은 도착 판단에만 사용하며 이동 경로는 저장하지 않습니다. 모든 대상의 도착 기록이 저장되면 GPS 감지를 중지하고, 운행 종료 버튼으로 종료 시각을 저장합니다.

운행 감지 서비스가 실행 중이면 화면 꺼짐·홈 이동 중에도 기록하도록 구현했습니다. 강제 종료 또는 OS에 의한 서비스 중단 후에는 앱에서 감지를 재개해야 합니다. 기기별 절전 정책에서의 실제 동작은 별도 검증이 필요합니다.

승하차 장소 선택 지도는 유지합니다. 배경 지도는 인터넷이 필요하며 OpenStreetMap 서버에 표시 영역의 타일을 요청합니다.

## 최소 실행 요구사항

2026-10-23부터 **Android 14(API 34) 이상**을 지원합니다(`minSdk = 34`). Android 13 이하에서는 새 버전의 설치·업데이트가 불가능합니다. 기존 설치본이 자동으로 삭제되는 것은 아닙니다. `targetSdk`와 `compileSdk`는 37을 유지합니다.

아래 2026-10-21 보안 보고서와 Android 9 계측 결과는 최소 버전을 올리기 전의 검증 이력입니다. 변경 후 Android 14 이상 기기에서 GPS·지도·저장·내보내기 동작을 별도로 검증해야 합니다. 최소 OS 상향만으로 앱의 잔여 보안 위험이 해결되는 것은 아닙니다.

## 보안 범위

2026-10-21: 최신 소스 7589268의 MobSF 정적 분석 및 제한된 동적 검사를 수행했습니다. 지도 타일 캐시 잔존을 확인했으며 API 감시와 TLS 검증은 미완료입니다. [보안 검사 현황·한계·후속 점검](SECURITY-TEST-2026-10-21.md)을 참고하세요. 이전 빌드의 36점과 이번 분석본의 56점은 동일 조건 비교가 아닙니다.

앱 내부 데이터는 Android Keystore의 AES 키로 암호화해 내부 저장소에 보관합니다. 백업 제외와 화면 캡처 제한을 설정했습니다. 키에 사용자 인증을 강제하는 설정은 없습니다. 기기가 잠금 해제된 상태이거나 화면 잠금이 설정되지 않았다면 앱에 자동 진입하므로, 별도의 사용자 인증 경계로 보아서는 안 됩니다. [코드 기반 보안 분석 보고서](SECURITY-REVIEW-2026-10-19.md)에 확인된 통제와 한계, 미검증 항목을 정리했습니다.

## 빌드와 검증

Android Studio에서 프로젝트를 열고 기존 Gradle/JDK/SDK 설정을 사용합니다. 정확한 위치 권한과 GPS가 필요합니다.

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-debug.ps1 -Offline -NoDaemon -NoConfigurationCache

## 좌표 중심 장소 저장 (v6)

주소 검색어와 검색 결과 주소는 등록 화면에서 지도 초기 위치를 찾는 임시 데이터입니다. 저장 시 장소 이름, 최종 위도·경도와 어르신 연결을 보관하고, 주소 문자열은 장소 및 운행 대상 스냅샷 JSON에 기록하지 않습니다. 저장 완료 후 등록 화면을 닫아 임시 검색 상태를 해제합니다. 수정 화면은 기존 좌표에서 시작하며 주소는 빈 검색창으로 표시됩니다.

기존 v1~v5 암호화 자료는 앱이 자료를 열 때 v6로 원자적으로 다시 저장하여 장소 및 과거 운행 대상의 주소 필드와 이동 경로 데이터를 제거합니다. 좌표가 없는 구형 장소는 추정 좌표를 만들지 않고 재지정 안내를 표시합니다. v6 저장 이후 구버전으로 되돌리면 자료를 읽을 수 없습니다. 기기에 이미 내보낸 파일이나 외부 검색 서비스에 전달된 검색어, 저장장치의 삭제 흔적에 대한 물리적 완전 삭제를 보장하지 않습니다.

좌표 역시 정확한 위치 정보입니다. 주소 검색 서비스 및 온라인 지도 타일 통신은 유지되므로 완전한 오프라인 앱은 아닙니다. 새 기기에 처음 설치하는 APK에는 테스트 중 기기에 입력한 자료가 포함되지 않습니다.

## 보안 종합 점검 보고서 (2026-10-21)

**판정: 주요 저장 보호와 검증은 구현되어 있으나, 모든 동적 과정에 보안 문제가 없다고 보증할 수 없다.** 온라인 지도/주소 검색의 외부 통신, 지도 캐시, 잠금 해제된 기기 접근, 평문 XLSX, 과거 기록 보존에 대한 잔여 위험이 있다. 이 문서는 코드 검토·자동 테스트·이전 MobSF 실행 증거를 구분하며 침투 테스트 완료나 보안 인증을 의미하지 않는다.

### 대상과 근거

- 기준 소스: `f0f483d` 이후 이 보고서와 함께 커밋한 Sparrow 예외 처리 보완, GPS SecurityException 처리 및 테스트 수정. 업로드 시 원격에서 발견한 `4780c9e`(저장 finally 복구·좌표 null 방어·Geocoder/서비스 예외 구분)도 보존하여 병합하고 재검증했다. 해당 문서가 포함된 커밋의 코드를 대상 범위로 본다.
- 현재 코드 검증: 로컬 Gradle Debug 빌드/단위 테스트/Lint, 별도 Android 9(API 28) 가상 기기 계측 테스트. 테스트 APK는 Debug 서명이며 운영 Release의 동일성이나 보안성을 증명하지 않는다.
- 이전 실행 증거: `7589268` Release 분석용 서명 APK의 MobSF 정적 분석 및 서울시청 가상 장소 검색→선택→저장, 내부 파일/캐시 검사. [MobSF 범위와 한계](SECURITY-TEST-2026-10-21.md).
- Sparrow: 표시된 21건의 소스 검토와 수정/보류 사유는 [별도 보고서](SPARROW-REVIEW-2026-10-21.md). 이번 수정본을 Sparrow/MobSF에 다시 업로드하거나 재점수화하지 않았다. 이전 빌드 36점과 별도 분석본 56점은 직접 비교 불가.
- 개인정보가 없는 가상 자료로 검사했다. 원본 기기 로그·분석용 키·APK·앱 데이터 추출본은 Git에 올리지 않는다.

### 우선 해결·결정할 사항

1. **개인정보 접근·보존 정책:** 잠금 해제 기기에서 누구나 앱에 접근 가능한 현재 동작, 과거 운행 스냅샷 보존, 평문 내보내기를 운영자가 명시적으로 이해해야 한다. 독립 인증/자동 잠금/키 인증 연동은 백그라운드 운행 저장과 충돌할 수 있으므로 설계와 회귀 검증 후 변경해야 한다.
2. **지도 캐시와 통신:** 타일 캐시 잔존을 해결하려면 암호화 캐시/적합한 제공자/오프라인 지도 등을 설계 검토해야 한다. OSM 공용 타일 정책은 HTTP 캐시 준수를 요구하므로 캐시를 무조건 꺼서 매번 재다운로드하는 변경은 하지 않았다. [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/), [OSMF 개인정보 정책](https://osmfoundation.org/wiki/Privacy_Policy).
3. **WebView 경계 실증:** `shouldInterceptRequest`는 리디렉션의 최초 URL에만 호출될 수 있어 콜백만으로 모든 최종 목적지가 통제된다고 주장할 수 없다. 현재 CSP도 함께 작동하지만 우회·리디렉션·인증서 오류를 실제 WebView 버전별로 검사해야 한다. `unsafe-inline` CSP 및 경로/포트 제한의 강화도 기능 검증 후 검토한다. [Android WebViewClient](https://developer.android.com/reference/android/webkit/WebViewClient).
4. **런타임/네트워크 추가 검사:** TLS/MITM·인증서 오류 거부·앱별 트래픽 분리·Geocoder 실제 목적지·메모리/로그·키 접근·GPS 권한 철회·장시간 백그라운드 동작을 미완료 항목으로 남긴다. 이전 MobSF API 감시 기록은 비어 있었으며 이번 검토로 해결됐다고 볼 수 없다.
5. **가용성과 공급망:** 이름/데이터 전체 크기의 명시적 상한이 없어 대량 자료에서 메모리/저장 실패 가능성이 있다. 구형 Geocoder worker의 중단 불가 호출/대기열도 부하 테스트 필요. 검사 당시 Android 7 최소 지원(2026-10-23부터 Android 14로 상향), 구형 의존성, 번들 Leaflet/WebView 공급망의 전수 CVE 검사는 미완료다. 도구의 업데이트 권고가 현재 최신 버전 확정이나 취약점 입증을 뜻하지는 않는다.

### 이번 보완과 검증 결과

- Sparrow 관련 엑셀 예외 처리 보완과 회귀 테스트 3개 포함. 실패 시 정리 동작을 유지하고 취소 예외를 일반 오류로 바꾸지 않는다.
- GPS 서비스의 기존 권한 검사/일반 복구 경계에 `SecurityException` 전용 처리를 추가해 GPS 해제와 안내를 명확히 했다. Lint 경고를 억제하는 baseline/suppress는 추가하지 않았다.

### 검증의 경계

이번 점검은 주요 동적 **코드 경로**를 검토하고 자동화 가능한 일부 과정을 실행한 결과다. 실사용 모든 동적 과정·모든 기기·모든 외부 서버에 대한 완전한 공격 검증은 아니다. Android 9 테스트 결과를 최신 Android 및 운영 Release에 일반화하지 않는다. Geocoder 결과는 제공자 최선 추정이며 정확도·가용성이 보장되지 않는다. [Android Geocoder](https://developer.android.com/reference/android/location/Geocoder).

최종 배포 키로 서명한 Release APK의 해시를 고정한 뒤 최신 지원 Android와 실제 기기에서 위 미완료 항목을 재검증해야 한다. 코드가 Git에 올라간 것과 GitHub Releases의 APK 갱신은 별개이며, 이번 업로드는 소스·테스트·문서다.
