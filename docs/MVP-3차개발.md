# MVP 3차 개발 — 백그라운드 운행 감지와 결과 안내

기준일: 2026-10-18. 2차의 정차 판정·저장 모델을 유지하고 위치 수신의 소유자를 화면에서 서비스로 옮겼다.

## 구현 범위

- TripLocationService가 location 유형 foreground service로 실행된다. 사용자가 앱 화면에서 운행을 시작하거나 감지 재개를 눌러 시작한다.
- 화면 꺼짐, 홈 이동, 앱 잠금, 화면 회전 중에도 서비스가 GPS 수신·20초 판정·암호화 저장을 담당한다. 앱 자료를 보려면 기존 기기 인증이 필요하다.
- 운행 알림에는 이름·주소·좌표를 넣지 않는다. 알림을 누르면 앱 잠금 화면을 통해 진입한다. 알림 권한이 꺼져 있으면 화면에 허용/설정 버튼을 표시한다.
- 시작 전 위치 권한과 GPS 설정을 확인한다. 운행 도중 GPS 꺼짐·권한 해제·수신 끊김은 상태 메시지와 알림으로 안내하고 미완료 정차 시간을 초기화한다.
- OS가 프로세스를 종료하거나 사용자가 앱을 강제 중지하면 자동 재시작하지 않는다(START_NOT_STICKY). 앱을 다시 열었을 때 저장된 진행 중 운행과 실제 서비스 상태를 비교하여 감지 중단과 재개 버튼을 표시한다. 재부팅 자동 시작도 구현하지 않았다.
- 운행 종료 또는 모든 대상의 기록 완료 시 위치 수신, foreground 알림, 서비스와 WakeLock을 해제한다. 모든 기록 완료로 GPS가 종료되더라도 운행 자체의 종료 시각은 사용자가 운행 종료를 눌러 저장한다.
- CPU 절전으로 정차 판정 루프가 멈추지 않도록 실제 GPS 요청 중에만 시간 제한이 있는 partial WakeLock을 유지한다. GPS가 꺼지거나 권한이 없으면 해제한다. 단말 제조사의 배터리 제한·강제 종료까지 지속 동작을 보장하지는 않는다.

## 표시 개선

- **장소 판정 반경 50m / 현재 GPS 오차 약 5m**를 다른 항목으로 표시한다. GPS 오차 허용 기준은 30m 이하이다.
- 운행 중 기록 완료·미기록·저장 대기 인원과 실제 서비스 상태를 보여준다.
- 종료 확인창에서 미기록 인원과 대상/장소를 확인한다. 저장 대기 기록은 종료 시 함께 저장한다.
- 운행 목록에도 기록/미기록 수를 표시하고 상세에서 어르신별 도착 추정 시각을 확인한다.

## 동시 저장과 종료

SecureCareStore.update는 최신 파일 읽기→변경→검증→암호화 저장 전체를 기존 공통 잠금 안에서 처리한다. UI의 장소/어르신 수정과 서비스의 자동 기록이 서로의 변경을 덮어쓰지 않는다. 저장 변경 알림은 메모리의 revision 숫자만 전달하며 잠금 해제된 화면이 저장 자료를 다시 읽어 반영한다.

종료 버튼 확정 시 메인 스레드의 종료 플래그로 새 GPS 판정을 즉시 차단한다. 이미 확인된 대기 기록을 최신 파일에 병합하고 종료 시각을 한 번에 저장한다. 종료 저장 실패 시 플래그를 해제하여 다시 감지/저장할 수 있게 한다. 종료 이후 도착한 서비스 저장 요청은 자료를 변경하지 않는다.

파일 형식은 기존 JSON v3 및 CAR1 암호화 봉투를 유지한다. v1/v2 읽기 호환성, 키 별칭, 백업 제외 규칙은 변경하지 않았다. 저장에 성공하기 전 메모리의 대기 기록은 강제 종료 시 유실될 수 있으며 완료 인원으로 표시하지 않는다.

## Android Studio에서 직접 확인

1. 프로젝트를 빌드·실행하고 기기 인증으로 앱을 연다.
2. 가상 어르신을 위도 37.5, 경도 127.0인 가상 장소에 연결한다.
3. 운행을 시작한다. 정확한 위치 권한을 허용하고 GPS가 켜져 있는지 확인한다. 필요하면 **GPS 감지 시작·재개**를 누른다.
4. **운행 알림 허용·설정**이 보이면 허용한다. 위치 수신 대기/정차 확인 상태와 운행 알림을 확인한다. 앱을 너무 빨리 벗어나 서비스 시작이 거절된 경우 다시 앱에서 재개한다.
5. 에뮬레이터의 전원 버튼으로 **화면을 끈다**. 에뮬레이터 자체를 종료하거나 프로세스를 종료하는 동작과 다르다.
6. Android Studio PowerShell 터미널에서 아래 명령으로 25초간 가상 위치를 보낸다.
7. 화면을 켜고 다시 인증하여 도착 기록을 확인한다. 모든 대상이 기록됐다면 GPS와 운행 알림은 이미 종료될 수 있다.
8. 운행 종료를 누르고 미기록 인원을 확인한 뒤 종료한다. 이후 위치를 보내도 추가 기록이 없어야 한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\simulate-gps.ps1 -Latitude 37.5 -Longitude 127.0 -Seconds 25
```

| 상황 | 기대 결과 |
| --- | --- |
| 홈으로 이동 또는 앱 잠금 | 서비스가 살아 있으면 계속 기록, 앱 자료 확인은 재인증 |
| GPS 껐다 켜기 | 중단 안내, 복구 후 새로운 20초부터 확인 |
| 정확한 위치 권한 해제 | 감지 중단. OS가 앱을 종료할 수 있으며 재실행 후 권한 허용·재개 |
| 강제 중지 후 앱 재실행 | 기존 운행/저장 기록은 유지, 감지 중단과 재개 버튼 표시 |
| 미기록 대상이 있는 채 종료 | 종료 전 인원/대상 확인, 임의 도착 기록 생성 없음 |
| 운행 도중 장소·어르신 수정 | 시작 당시 운행 스냅샷과 이미 저장된 도착 기록 보존 |
| 알림 거부 | 앱에서 알림 비활성 안내. Android 버전에 따라 알림 목록 대신 시스템 작업 관리자에 서비스 표시 |

## 검증

- assembleDebug / testDebugUnitTest / assembleDebugAndroidTest 빌드 성공.
- 로컬 테스트 총 **30개 통과, 실패 0**. 기존 24개 + 서비스 상태/종료 관련 6개.
- 새 로컬 테스트: 실제 서비스 없는 저장 운행의 중단 표시, 이전 운행 서비스 상태 분리, 완료·권한 상태, 종료 플래그/실패 복구, 종료 후 늦은 쓰기 차단, 종료 시 대기 기록 병합.
- 기기 테스트에는 서로 다른 저장소 인스턴스의 동시 수정/자동 기록과 잘못된 트랜잭션의 기존 파일 보존을 추가했다. 컴파일을 확인했으며 이번 단계의 기기 실행은 하지 않았다.
- 화면 꺼짐 상태에서 실제 GPS 수신·서비스 지속·알림·권한 변경은 사용자가 위 절차로 검증한다. 이전 단계의 기기 테스트 결과를 이번 버전의 검증으로 간주하지 않는다.
- Lint는 이번 단계에서 실행하지 않았다. Gradle/JDK/SDK와 앱 ID/서명 설정은 변경하지 않았다.

## Android 요구사항과 다음 범위

Manifest에 FOREGROUND_SERVICE, FOREGROUND_SERVICE_LOCATION, POST_NOTIFICATIONS, WAKE_LOCK과 비공개 location 서비스를 추가했다. 백그라운드 위치 권한 없이 사용자가 보고 있는 앱에서 location foreground service를 시작하는 구조다.

공식 참고: https://developer.android.com/develop/background-work/services/fgs/service-types

엑셀 출력, 기록 수동 수정·이력, 프로세스 종료/재부팅 후 자동 운행 복구는 이후 범위다.
